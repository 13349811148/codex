# Design: Desktop Finance MVP

## Overview
本设计定义财务统计小工具当前版本的实现方案，重点包括：

- 桌面批量导入
- 平台与店铺识别
- 来源模板解析
- 分类映射
- 分类汇总导出
- 贷借法双金额列输出

## Architecture
系统采用四层结构：

1. `UI`
   - 数据目录选择
   - 保存文件对话框
   - 处理结果和异常展示

2. `Application Services`
   - 导入、分类、汇总、导出流程编排

3. `Domain`
   - 文件名解析
   - 来源识别
   - 金额标准化
   - 备注归一化
   - 分类映射
   - 汇总计算

4. `Infrastructure`
   - 文件系统访问
   - CSV/XLS/XLSX 读取
   - SQLite
   - Excel 导出

## Runtime Flow
```text
选择数据目录
-> 选择导出文件
-> 扫描支持文件
-> 解析平台与店铺
-> 识别来源模板
-> 调用解析器
-> 标准化记录
-> 分类映射
-> 跳过忽略记录
-> 聚合生成汇总表
-> 导出 Excel
```

## Parsing

### Pinduoduo
- 文件类型：`CSV`
- 跳过前 4 行说明
- 第 5 行作为表头

字段：
- `商户订单号`
- `发生时间`
- `收入金额（+元）`
- `支出金额（-元）`
- `账务类型`
- `备注`
- `业务描述`

### Taobao
- 文件类型：`XLSX/XLS`
- `原始数据` sheet
- 第 3 行作为表头

字段：
- `商户订单号`
- `入账时间`
- `收入（+元）`
- `支出（-元）`
- `账务类型`
- `备注`
- `业务描述`

## Normalization

### Month
- 拼多多：由 `发生时间` 提取
- 淘宝：由 `入账时间` 提取

### Amount
- 收入转为正数
- 支出转为负数
- 空金额或双金额记录记异常并跳过

### Taobao Remark
淘宝备注做归一化，保留稳定业务文本，去除编号、订单号和邮箱等动态信息。

## Classification

### Taobao
键：
`remark_norm + " —— " + biz_desc`

`[空] —— [空]`：
- 标记为 ignored
- 不参与汇总

### Pinduoduo
键：
- `biz_desc`

重点已确认规则包括：
- `0040003|售后费用-运费补偿` -> `运费补偿 / 售后费用`
- `0040005|售后费用-虚假发货` -> `虚假发货 / 售后费用`

说明：
- 这两条规则已按最新业务口径从原来的 `店铺费用` 调整为 `售后费用`

## Aggregation
当前导出使用分类汇总长表，每行对应：

- `month`
- `store_name`
- `platform`
- `major_category`
- `detail_category`

导出列为：

- `月份`
- `店铺名`
- `平台`
- `大类`
- `明细分类`
- `收入金额`
- `支出金额`
- `记录数`

## Debit/Credit Output
内部仍使用单一 signed amount 进行计算，但导出时采用双金额列：

- `收入金额`
  - 只汇总大于 0 的金额
- `支出金额`
  - 只汇总小于 0 的金额，导出时取绝对值

这样既保留业务分类，又满足财务按借贷式双列查看金额的需求。

## Export
- 单个 Excel 文件
- 单个 sheet：`总汇总表`
- 导出前弹出保存文件对话框

## Persistence
SQLite 保存：
- 默认输入目录
- 最近导出目录
- 运行日志

## Verification
当前版本验证目标：
- 能读取真实淘宝和拼多多样本
- 能导出包含 `大类` 和 `明细分类` 的汇总表
- 能导出 `收入金额` 和 `支出金额`
- 拼多多 `虚假发货` 与 `运费补偿` 显示为 `售后费用`
