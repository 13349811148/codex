# Design: Desktop Finance MVP

## Overview
本设计定义财务统计小工具 `MVP` 的技术实现方案，包括系统架构、模块职责、数据结构、解析流程、分类策略和导出规则。

## Architecture
系统采用四层结构：

1. `UI 层`
   - 主窗口
   - 数据目录选择
   - 导出文件保存对话框
   - 结果与异常展示

2. `应用服务层`
   - 运行总流程编排
   - 文件扫描与解析调度
   - 分类、汇总、导出调用

3. `领域逻辑层`
   - 文件名解析
   - 来源识别
   - 金额标准化
   - 备注归一化
   - 分类映射
   - 汇总计算

4. `基础设施层`
   - 文件系统访问
   - `CSV/XLS/XLSX` 读取
   - `SQLite` 持久化
   - `Excel` 导出

## Runtime Flow
```text
选择数据目录
-> 选择导出路径
-> 扫描支持文件
-> 逐文件解析平台与店铺
-> 识别来源模板
-> 调用解析器读取原始记录
-> 标准化时间、金额、备注
-> 按平台规则分类
-> 过滤忽略记录
-> 生成分类汇总表
-> 导出 Excel
-> 返回运行结果
```

## Modules

### UI
主窗口包含：
- 数据目录输入框
- 浏览按钮
- 一键生成报表按钮
- 运行状态
- 处理结果摘要
- 导出路径展示
- 异常列表

### Import Service
职责：
- 扫描支持文件
- 为每个文件创建处理任务
- 根据来源类型选择解析器

### Parser Layer
当前支持：
- `pdd_csv`
- `tb_xlsx`

#### PddCsvParser
- 跳过前 4 行说明
- 第 5 行作为表头
- 提取 `商户订单号`、`发生时间`、`收入金额（+元）`、`支出金额（-元）`、`账务类型`、`备注`、`业务描述`

#### TbXlsxParser
- 读取 `原始数据` sheet
- 第 3 行作为表头
- 提取 `商户订单号`、`入账时间`、`收入（+元）`、`支出（-元）`、`账务类型`、`备注`、`业务描述`

### Filename Parser
从文件名提取：
- `platform`
- `store_name`

规则：
- 平台关键词优先匹配 `拼多多`、`淘宝`、`天猫`、`京东`
- 去除扩展名和 `（下载）`
- 取平台关键词后的文本作为店铺名

### Normalization

#### Month
- `拼多多`：从 `发生时间` 提取 `YYYY-MM`
- `淘宝`：从 `入账时间` 提取 `YYYY-MM`

#### Amount
- 收入列有值 -> 正数
- 支出列有值 -> 负数
- 收入和支出同时为空或为 `0` -> 记录异常并跳过
- 收入和支出同时有值 -> 记录异常并跳过

#### Remark Normalization
仅淘宝采用归一化：
- 去除订单号、邮箱、括号中的动态信息
- 保留可用于分类的稳定文字
- 示例：`基础软件服务费(2701768802023008263)扣款` -> `基础软件服务费扣款`

### Classification

#### Taobao
分类键：
`remark_norm + " —— " + biz_desc`

特殊规则：
- `[空] —— [空]` -> `ignored`
- 不进入统计

产出字段：
- `detail_category`
- `major_category`

#### Pinduoduo
分类键：
- 优先 `biz_desc`

已确认的关键分类包括：
- `0010002|交易收入-订单收入` -> `销售收入 / 资金到账`
- `0010005|交易收入-优惠券结算` -> `销售收入 / 资金到账`
- `0130005|其他收入-申诉补回` -> `销售收入 / 资金到账`
- `0090001|平台补贴-补贴汇入` -> `补贴金额 / 资金到账`
- `0030001|技术服务费-技术服务费` -> `技术服务费 / 店铺费用`
- `0030002|技术服务费-基础技术服务费` -> `基础软件服务费 / 店铺费用`
- `0030023|技术服务费-黑标技术服务费` -> `技术服务费 / 店铺费用`
- `0030003|技术服务费-百亿补贴技术服务费` -> `技术服务费 / 店铺费用`

## Aggregation
当前导出采用“分类汇总长表”结构，每行代表一个分类维度组合：

- `月份`
- `店铺名`
- `平台`
- `大类`
- `明细分类`
- `金额`
- `记录数`

`记录数` 定义：
- 指参与当前分类汇总行统计的原始明细条数
- 仅统计成功解析且成功分类的记录
- 忽略记录和异常记录不计入

## Export
运行时弹出保存文件对话框，由用户选择导出位置和文件名。

输出：
- 单个 `Excel` 文件
- 单个 sheet：`总汇总表`

列结构：
- `月份`
- `店铺名`
- `平台`
- `大类`
- `明细分类`
- `金额`
- `记录数`

## Persistence
`SQLite` 用于保存：
- 默认输入目录
- 最近一次导出目录
- 运行日志

表：
- `app_config`
- `mapping_rules`
- `run_logs`

## Error Handling
异常类型：
- 文件打开失败
- 来源模板未识别
- 文件名解析失败
- 时间字段缺失
- 金额字段异常
- 分类规则未命中

异常策略：
- 单条异常不影响整文件
- 单文件异常不影响整批处理
- 所有异常显示在 UI 中

## Constraints
- 当前不导出原始明细
- 当前分类规则以代码内置为主
- 当前不提供规则管理界面

## Verification
最低验证项：
- 能读取两个真实样本
- 能正确识别平台和店铺
- 能生成包含 `大类` 和 `明细分类` 的汇总报表
- 导出前弹出保存文件对话框
